# Evidence Before Claims

> If I claim I can do something, I should be able to show how I approached it.

The site should earn trust through artefacts and reasoning rather than adjectives.

Useful evidence includes:

- working demonstrations;
- architecture diagrams;
- selected source excerpts;
- screenshots;
- benchmarks;
- before-and-after comparisons;
- decision records;
- lessons from failed approaches;
- links to public repositories;
- guided access to private repositories where appropriate.

Evidence must be proportionate. A project page should not become a data dump, and a prototype should not be described as production software.

Where evidence cannot be published because of confidentiality, ownership or security, the limitation should be stated plainly.

## Test

For every meaningful claim, ask:

- What supports it?
- Can that support be shown?
- Is the wording stronger than the evidence?
- Would I defend the statement in an interview?
