# Requests for Comment

RFCs are proposals that need discussion before they become accepted product or architectural decisions.

Use an RFC when an idea:

- changes the product model;
- introduces a significant dependency or service;
- affects several areas of the site;
- has meaningful trade-offs;
- needs a prototype or feedback before commitment.

Do not use an RFC for routine implementation details already covered by accepted specifications.

## Lifecycle

1. Draft
2. Proposed
3. Review
4. Accepted, Rejected or Withdrawn
5. If accepted, create or update the relevant ADR/specification

## Naming

`RFC-NNN-short-title.md`

## Template

Use [`RFC-TEMPLATE.md`](RFC-TEMPLATE.md).
